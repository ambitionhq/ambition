先说结论：**老板要的其实不是 Excel，是每天早上花 30 秒就知道"昨天生意好不好、有没有事要我拍板"。** 一张原始订单表等于把分析的活儿推给了他，他多半不会点开附件。

所以更有野心的做法是：把这个脚本从"导出工具"升级成**店铺的每日经营简报，外加一套数据底座**。工作量比你原计划多不了太多，价值却高一个量级。

## 1. 先想清楚：老板早上 8 点收到的是什么

不是一个附件，而是一条在手机上一眼就能看完的消息（下面是假数据示例）：

```
【昨日简报】10月26日 周一
销售额 $12,480（比上周一 +18%，比近 4 周周一均值 +11%）
订单 156 ｜ 客单价 $80 ｜ 新客占比 42%

一句话：增长主要来自"秋季套装"（$3,100），多数用了 FALL15 折扣码，流量来自 Instagram。

需要你注意：
1. 退款率 5.8%（平时约 2%），8 笔集中在某外套 M 码，原因多为"尺码不合"
2. 这款外套 M 码按近 7 天的销速，大约 4 天后断货
3. 有 11 笔订单超过 48 小时还没发货

明细见附件（已去掉客户隐私信息）
```

Excel 还保留，只是降级成附件，留给想深挖的人。

## 2. 支撑它的几层能力，可以逐层加

1. **数据沉淀（最关键的一步）**：每天把订单增量同步进自己的数据库，SQLite 起步就够。有了历史数据才能做"比上周同日"这类对比。还有一个很现实的理由：Shopify API 默认只能读最近 60 天的订单（更早的要额外申请 `read_all_orders` 权限），所以越早开始存越好。
2. **指标和对比**：销售额、订单数、客单价、新老客、Top SKU、折扣码、退款、流量来源。重点是**跟上周同一天、近 4 周同一天的均值比**，不要跟前一天比。电商的星期效应很强，周一跟周日比没有意义。
3. **异常和预警**：先用简单规则，不用一上来就搞模型。比如退款率超过阈值、某个 SKU 按 7 天销速 N 天内会断货、订单超时未发货、被 Shopify 标成高风险的订单。
4. **AI 一句话解读**：把算好的数字交给大模型，让它写 3 到 5 句人话总结。铁律是**所有数字由代码算好再传给它，它只负责措辞，不许自己算**，否则迟早会编出一个错误数字。
5. **送达渠道**：放在邮件正文里，不要只放附件。如果公司用飞书、企业微信或钉钉，机器人推送比邮件更适合手机阅读。

再往上，是真正"厉害"的部分：

- **盘中预警，而不是第二天才知道**：比如到中午销售额只有平时同时段的 40%，立刻推送提醒。这往往说明网站、支付或广告出了问题，第二天早上才发现就晚了。可以用 Shopify webhook 或 Flow 做大单、高风险单的实时通知。
- **看利润，不只看营收**：Shopify 每个商品规格都可以填成本价，再接上 Meta、Google、TikTok 的广告花费，就能算出每天的真实毛利和 ROAS。老板最关心的其实是这个数。
- **对话式查询**：老板在飞书里直接问"上个月哪个产品退货最多？"，由大模型去查你的数据库再回答。有了第 1 层的数据底座，这件事比听起来容易得多。

## 3. 我建议的路线

- **第 1 期（你原计划的升级版）**：订单入库，邮件正文里放核心指标和同比，Excel 作附件，部署到云上定时跑，失败时自动告警。
- **第 2 期**：异常规则、AI 解读、推送到飞书或企业微信。
- **第 3 期**：成本加广告花费算利润，加上盘中预警和对话查询。

第 1 期只比你原来的想法多两件事："顺手存一份数据"和"把正文写好"。但做了这两件，后面每一期都有地基。

## 4. 几个会毁掉老板信任的坑，第一天就要处理

- **数字必须和 Shopify 后台报表对得上**："昨天"要按店铺时区切，不能按服务器时区；要排除测试订单；取消单怎么算、退款算在哪一天（退款常常发生在下单后的另一天）、用毛销售额还是净销售额、多币种怎么处理，都要定好口径。老板只要拿后台一对，发现数字不一样，这份报表就废了。建议上线前拿过去一周的数据，跟后台报表逐日对一遍账。
- **用 GraphQL Admin API**：官方已经把 REST API 标成了 legacy，新项目别再用 REST。
- **别跑在你自己的电脑上**：用 GitHub Actions 定时任务、云函数或一台小服务器。还要有"今天没发出去就通知你"的机制，别让老板先发现报表断了。
- **附件里别带客户隐私**：姓名、地址、电话、邮箱老板用不上，邮件被转来转去还有合规风险，有欧盟客户的话尤其要注意。
- **邮件用企业邮箱的 SMTP 或事务邮件服务发**，密钥放环境变量里，别把个人邮箱密码写进脚本。

## 5. 动手前，值得先问老板（或问自己）三个问题

1. 他看完这份东西，通常会做什么决定？补货、调广告，还是催发货？答案决定了报告里该放什么。
2. 他在哪里看？邮箱、微信还是飞书？用手机还是电脑？
3. 有没有成本价和广告花费的数据？这决定了能不能做到"利润"那一层。

顺带提一句：如果最后发现只需要最基础的汇总邮件，Shopify Flow（定时触发、获取订单数据、发送内部邮件）或者应用商店里的定时报表 App，可能不写代码就能搞定，值得先花二十分钟试试。真正值得自己写代码的，是它们做不到的那些：历史对比、异常预警、AI 解读、利润和对话查询。
