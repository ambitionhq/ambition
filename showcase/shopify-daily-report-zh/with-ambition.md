## 野心阶梯：每天把 Shopify 昨日订单发给老板

**Rung 0 · 原始需求：** 写个 Python 脚本，每天早上把前一天的订单导出成 Excel，邮件发给老板。
手上有：Shopify 店铺、邮箱、Python。还没有：API 只读权限，也还不清楚老板拿到这份 Excel 之后具体做什么。

**最合适的方向：** 高度 + 深度。这是一份每天重复的报告，老板看它是为了判断"昨天有没有出事、要不要处理"，所以值得直接往这个判断上爬。原始订单数据也是现成的，可以用统计方法代替肉眼扫表。广度只借一样东西：工厂盯生产线用的"统计过程控制"，专门用来分辨一个数字是正常波动还是真出了问题。

### Rung 1 · 加强版：深度
Excel 和邮件照旧，但正文前三行直接回答：昨天和过去 4 个同一星期几相比变了什么，主要是哪个商品或渠道带来的变化。数据从 Shopify API 拉原始订单，不用后台导出的 CSV。
裁判：连续 14 天和 Shopify 后台"销售额"报表对账，差异不超过 0.5%；老板不打开附件也能说出昨天发生了什么。

### Rung 2 · 大胆版：高度 + 深度  ← 推荐
把日报改成预警。每天 8:00 前算 8 到 10 个核心指标（销售额、订单数、客单价、退款率、超过 48 小时还没发货的订单数、热销款还能卖几天等），每个指标都和它的**控制限**比较，控制限就是"这个指标在这个星期几的正常范围"，用过去 8 周的数据算。正常的日子只发一行"全部正常"。超出范围时，自动按商品、渠道、地区、折扣码、退款原因往下拆，找出问题出在哪一块。上线前先做**回测**，也就是拿过去 12 个月的数据模拟它当时就在每天运行：团队记得的事故，至少 80% 要能在当天的早报里被标出来，误报每周不超过 1 次。
需要：Shopify 只读 API、12 个月订单历史、一份过去的事故清单 · 裁判：回测结果对照团队自己列的事故清单；后台报表对账；并行跑 4 周后，请老板标出哪些预警他真的会去处理

### Rung 3 · 颠覆版：高度
往根上问一句：老板真的需要日报吗？他真正要的是店铺运转正常。可以改成一个值班助手：每小时巡检一次，发现异常就起草处理动作，比如暂停某个折扣码、给快断货的款起草补货单、把高风险订单标出来等人审核，老板一键批准。先和现有日报并行影子运行 30 天，只起草、不执行。· 裁判：起草的动作里老板愿意批准的比例，以及比人工发现提前了多少小时

**推荐 Rung 2。** 只需要一个只读权限就能做。正常的日子老板只读一行，出事的日子拿到的信息比整张 Excel 还多。Rung 3 需要写权限和老板的信任，Rung 2 跑满一个月的记录就是在攒这份信任。

**需要解锁：**
- 一个只读的 Shopify 自定义应用和 Admin API 令牌，权限勾 read_orders、read_products、read_inventory，**还要单独勾 read_all_orders**，不然 API 只给最近 60 天的订单，没法做 12 个月回测（待设置）
- 过去一年的事故清单：哪天断货、哪天广告停了、哪天结账出了问题。找团队聊 30 分钟就能列出来（待设置）
- 一个不关机的定时运行环境，比如 GitHub Actions 或一台小云服务器，不要放在自己电脑上跑（待设置）
- 邮箱发信（已有）。附件只放汇总数据，不放客户姓名、邮箱、地址
- 老板这边：他要的是 Excel，你给的是预警，先跟他打个招呼。头 4 周 Excel 照发，预警写在邮件正文里（待沟通）

**信任风险：**
- 数字和后台对不上（时区、退款、运费、税的算法不一致）→ 按店铺时区划分日期，算法照搬后台"销售额"报表；前 14 天每天对一次账，对不上就先不发给老板。
- 静默失败：某天令牌过期或 API 报错，什么都没发出去，老板以为一切正常 → 每天必须发一条，数据不完整时在早报里写明，同时通知你。

**便宜路线：** 如果你只要 Rung 0，Shopify 应用市场里的报表应用（比如 Better Reports、Report Pundit）本身就能定时把订单 Excel 发到邮箱，不用写一行代码。

**大概长这样**（示意，数字是编的）：
```text
【昨日经营 · 10/27 周二】⚠ 1 项异常，其余 9 项正常

⚠ 退款率 6.8%（周二正常范围 1.6%–3.9%）
   14 笔退款里有 11 笔来自「羊毛围巾-灰」，其中 8 条退款备注提到"色差"
   这款从 10/21 起退款明显变多，之前 8 周平均退款率 1.2%
   建议：今天先停这款的广告，查一下最近到的这批货

✓ 销售额 $32,033（正常 $27k–$36k）· 订单 206 · 客单价 $155.5
✓ 超 48 小时未发货：0 · 热销款可售天数都在 14 天以上
数据截至 10/27 23:59（店铺时区）· 口径同后台销售报表 · 明细见附件
```

**升级后的提示词**（复制粘贴即可）：
```text
目标不是"每天发一份订单 Excel"，而是让老板每天 8:00 前知道昨天店里有没有出问题、出在哪、该做什么；没问题的日子只占用他 10 秒。

数据：通过只读 Shopify 自定义应用（scope: read_orders, read_all_orders, read_products, read_inventory），用 Admin GraphQL API 的 Bulk Operations 拉过去 12 个月的原始订单、退款、履约和库存数据，存进本地 DuckDB。按店铺时区切日。不要用后台导出的 CSV。

方法：
1. 定义 8–10 个核心指标（销售额、订单数、客单价、退款率、超 48h 未发货单数、折扣码占比、新客占比、热销 SKU 可售天数），口径与 Shopify 后台"销售额"报表一致，写成带单元测试的函数。
2. 每个指标按"同一星期几、过去 8 周"算控制限（统计过程控制思路，用中位数 ± k·MAD 这类稳健统计），出界才算异常。
3. 出现异常时自动下钻（SKU / 渠道 / 地区 / 折扣码 / 退款原因），找出贡献最大的维度。只陈述算出来的数字，不要编造原因。
4. 输出：邮件正文一份 ≤8 行的早报，异常放最上面；Excel 只作附件，不含客户姓名、邮箱、地址。
5. 每天必发。脚本失败、数据不完整，或与后台报表差异 >0.5% 时，在早报里写明，并另外通知我。

硬指标：在我提供的过去 12 个月已知事故清单上回测，≥80% 的事故要在当天早报中被标出，误报每周 ≤1 次。这个目标是能做到的；达不到就调参数、换方法，记录每次尝试和结果。

裁判（不是你自己）：① 回测结果对照我给的事故清单；② 前 14 天每天和 Shopify 后台报表对账；③ 和现有 Excel 并行跑 4 周，最后由老板标出哪些预警他会采取行动。

先不碰生产环境：早报先只发给我，不发老板。先给我看指标口径和回测结果，我确认后再上线。
```

想开始的话说"开干"，我就按 Rung 2 推进（第一步是拿到只读令牌和整理事故清单），你也可以换一级台阶。
